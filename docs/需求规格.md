# 需求规格: 基于 Claude Code (cc-haha) 架构的下一代桌面端 AI Coding Agent

## 1. 项目背景与目标

深入调研 `D:\claude code`（开源项目 `cc-haha`）后，本项目确立以该项目的工业级架构为基准，在 `d:\Agent` 中构建一个兼具极速终端 CLI、独立本地 Server 与现代化 Electron 桌面工作台的 AI Coding Agent。

严格遵循 `evidence-driven-engineering`（证据驱动工程）规范：
- 零信任（Fail-closed）状态机与权限门禁
- 可验证的功能切片与强类型契约
- 高价值自动化测试套件与真实运行证据闭环
- 双层可观测性（开发过程审计 + 运行时 Trace/指标）

## 2. 核心架构借鉴点 (Derived from `D:\claude code`)

### 2.1 四进程拓扑解耦 (Four-Process Topology)
```text
Electron Main (宿主管理 / 原生窗口 / PTY / Sidecar 守护)
├── Chromium Renderer (React UI / Zustand / Shiki 高亮 / Diff 审阅)
├── Local Server Sidecar (HTTP REST / WebSocket 会话网关 / 局域网 H5 支持)
│   ├── /api/* 资源路由与会话持久化
│   ├── /ws/:sessionId 双向事件总线
│   └── /proxy/* 多厂商协议转换网关 (Anthropic / OpenAI / Ollama)
└── Agent Core / Subagents (异步生成器流式状态机)
    ├── General-purpose: 全功能主代理
    ├── Explore: 只读轻量探索子代理 (禁写，快速代码搜索)
    ├── Plan: 架构规划与分步执行计划子代理
    └── Verification: 独立对抗性验证子代理 (判定 PASS/FAIL)
```

### 2.2 核心 Agent 循环设计
- **放弃传统单向 ReAct**：转向基于 TypeScript `AsyncGenerator` 的流式状态机 (`query()`)。
- **流式边生成边执行 (Streaming Tool Execution)**：模型产出 `tool_use` 块即启动工具预热与执行，不等待全部文本结束。
- **工具并发编排策略 (Tool Orchestration)**：
  - **只读工具（Read-only）**：自动并行化（最多 10 并发，如 `Glob`, `Grep`, `FileRead`）。
  - **写入/破坏性工具（Write/Destructive）**：严格串行化，避免文件竞态与文件锁损坏。
- **分层提示词缓存边界 (System Prompt Pipeline)**：
  - 静态区域（角色、系统规则、工具描述）跨会话全局缓存。
  - 动态区域（CLAUDE.md、项目规范、环境信息、Token 预算）局部注入。
- **智能上下文压缩 (Context Compaction)**：
  - **Micro 压缩**：清除早期工具执行的大量冗长原始日志，保留提炼摘要。
  - **Auto 压缩**：Token 使用量达到阈值时自动触发 LLM 总结，避免截断或溢出。

## 3. 技术栈对齐清单 (Tech Stack Alignment)

| 模块 | 选型 | 说明 |
| :--- | :--- | :--- |
| **编程语言** | TypeScript (Strict Mode) | 全模块统一类型 |
| **桌面运行时** | Electron 34+ / electron-builder | 跨平台桌面外壳 |
| **桌面 UI** | React 19 + Vite 6 + Tailwind CSS | 60fps 现代化界面 |
| **状态管理** | Zustand 5 | 扁平、快速、无样板代码 |
| **代码高亮与 Diff** | Shiki + diff (jsdiff) | 工业级精确代码比对 |
| **本地终端** | `@xterm/xterm` + `node-pty` | 原生 PTY 支持彩色交互终端 |
| **后端/运行时** | Node.js (v24 LTS) / Bun 兼容 | 异步非阻塞 I/O，支持 HTTP 与 WebSocket |
| **模型协议** | `@modelcontextprotocol/sdk` + Provider Proxy | 原生支持 MCP 与多厂商 API 互通 |
| **测试框架** | Vitest | 极速单元与端到端状态机测试 |

---

## 4. 非目标 (Non-Goals)
- 本阶段不直接支持云端多租户 SaaS 部署，优先聚焦本地离线优先（Local-first）与桌面原生体验。
- 本阶段不引入重型无头浏览器常驻（如完整 Chromium 自动化沙箱），优先提供轻量 WebFetch 与系统浏览器唤起。
