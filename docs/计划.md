# 计划: 基于 Spec + TDD 驱动的 1:1 对齐开发路线图

本项目严格遵循 `evidence-driven-engineering` 与 **Spec + TDD (测试驱动开发)** 规范。
每个功能切片均遵守以下执行闭环：
`契约定义 (Spec/Contract) → 编写测试用例 (TDD Red) → 运行验证失败 → 实现最小可行代码 (Green) → 重构与留存证据 (Evidence)`

---

## 阶段规划与功能切片 (Slices)

### Slice 1: 工具并发编排调度器 (ToolOrchestrator)
- **契约**: [`docs/契约-Agent编排器与query状态机.md`](./契约-Agent编排器与query状态机.md)
- **TDD 目标**:
  1. 验证同构切片分区（连续只读合并为并行批次，写工具隔离为串行批次）。
  2. 验证多只读工具在并发限制（`maxConcurrency: 10`）下的真实并行执行。
  3. 验证写工具严格按原顺序单线程串行执行，杜绝文件锁与写覆盖。
- **测试文件**: `tests/orchestrator.test.ts`
- **执行命令**: `bun test tests/orchestrator.test.ts`

### Slice 2: AsyncGenerator 流式状态机 (Query Engine)
- **契约**: [`docs/契约-Agent编排器与query状态机.md`](./契约-Agent编排器与query状态机.md)
- **TDD 目标**:
  1. 验证 `query()` 的单层 `while(true)` 状态机，在多轮工具交互中通过 `state = next` 平铺流转，无深度递归。
  2. 验证模型产生敏感/破坏性工具时，状态机进入 `awaiting_confirmation`，挂起并等待 `onApprovalRequired` 决策。
  3. 验证用户批准后继续执行，用户驳回后优雅通知模型而不崩溃。
  4. 验证 AbortSignal 能够秒级终止整个异步生成器。
- **测试文件**: `tests/queryEngine.test.ts`
- **执行命令**: `bun test tests/queryEngine.test.ts`

### Slice 3: Bun.serve 本地服务与 SQLite 会话管理
- **契约**: [`docs/契约-服务端网关与会话持久化.md`](./契约-服务端网关与会话持久化.md)
- **TDD 目标**:
  1. 验证 `GET /health` 探针返回零延迟健康状态。
  2. 验证 `bun:sqlite` 对会话元数据（创建、列表、更新标题、删除）的 CRUD 完整性。
  3. 验证 WebSocket `/ws/:sessionId` 握手成功，正确派发 `connected` 与 `session_state`。
  4. 验证双向协议：客户端发送 `ping`，服务端返回 `pong`；客户端发送 `user_message`，触发流式事件推送。
- **测试文件**: `tests/server.test.ts`
- **执行命令**: `bun test tests/server.test.ts`

### Slice 4: Electron 桌面端双向打通 (Renderer <-> Bun Server)
- **契约**: UI 与 WebSocket 统一事件契约
- **TDD 目标**:
  1. Electron Main 进程守护拉起 Bun Server Sidecar。
  2. Renderer 端的 Zustand Store 订阅 WebSocket，流式还原 Thinking、Tool 卡片与终端输出。
  3. 界面人工审批卡片（ApprovalCard）与服务端的 `permission_response` 闭环。
