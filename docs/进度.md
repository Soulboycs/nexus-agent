## 诚实边界与非保证说明 (Honest Limitations & Non-Goals)

依据 `evidence-driven-engineering` 准则，必须明确记录当前版本**已证明成立的保证**与**明确不能声称的非保证**：

### ✅ 已证实保证 (Guaranteed by Evidence):
1. **Agent Loop 核心无递归**: 状态机完全平铺于 `query.ts` 异步生成器，异常中断或 Abort 触发自动补齐 `tool_result`，彻底杜绝 downstream API 400 格式错误。
2. **读写并发与安全隔离**: 只读工具并发度受控 (最高 10 路)，写与执行类工具严格串行互斥。
3. **长期记忆与上下文防爆**: 跨会话持久化遵循 `~/.nexus/projects/{hash}/memory/` 安全路径与 200行/25KB 双重截断；超限时以 `[compact_boundary]` 维持工具调用对完整性。
4. **多层级权限与沙箱防逃逸**: 严格执行 `deny > allow > ask` 与 `session > local > project > user`；路径越界遍历与高危命令正则拦截 100% 生效。
5. **Word 实时画布 1:1 纯内存联动**: 无论单块、多块选区、段落删除、表格插入或原子批处理格式，均在线内存就地流式应用并配合 OOXML Track Changes 软删除/插入标记，视口零跳顶。

### ❌ 明确不能声称的结论 (NOT Guaranteed):
1. **未支持跨物理机分布式 Subagent**: 当前 `SubagentEngine` 为单机单进程内存级子代理，尚未实现分布式多节点任务派发与负载均衡；
2. **未支持多用户并发抢占锁**: 当前设计专用于单用户本地 Electron 桌面端及本地服务端，未对多客户端同时写同一 Word 文件的分布式事务进行互斥锁管理；
3. **外部公网依赖健壮性**: 若用户网络无法访问 DeepSeek 公网 API，真实 E2E 功能必须降级至本地 Ollama 或离线 Mock 模式。
